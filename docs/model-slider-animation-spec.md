# Model Slider Animation Spec

## 1. 目标范围

本次只处理 `src/features/settings/ModelSettingsModal.tsx` 中两个能量滑块的以下动画问题：

- 轨道内“行星”移动方式
- “行星”滚动与位移的同步关系
- 拖尾粒子的生成、保留、遮盖消失逻辑
- 粒子在不同程度区间下的颜色与视觉变化

本次不处理以下内容：

- 模态框整体布局结构调整
- 文案修改
- 新增无关功能
- 为了“保险”而加入无意义兜底逻辑

## 2. 当前问题复述

根据最新反馈，当前实现存在以下问题：

1. 行星在用户点击目标程度后，会过快抵达目标位置。
2. 行星位移和旋转不是严格绑定的，出现“位置已经到了，但球还在转”的割裂感。
3. 粒子生成逻辑被改偏了，不符合原始设计意图。
4. 粒子的显隐逻辑没有严格遵守“向右产生、向左被遮盖消失”的规则。
5. 粒子颜色变化目前更像全局统一变化，而不是“只影响新经过区间内新出现的粒子”。

## 3. 需求解释标准

### 3.1 行星移动

行星不能在用户点击后“瞬间吸附”到目标程度。

正确效果应当是：

- 行星像一个具有重量和阻力的球体一样滚动到目标位置。
- 位移时要有惯性、阻力、缓冲感。
- 移动距离越长，整个滚动过程越明显。
- 移动距离越短，滚动过程越轻微，但仍然不是瞬移。

### 3.2 行星滚动

行星的滚动必须与位移严格同步。

正确效果应当是：

- 行星滚了多少距离，就转多少角度。
- 位移没有结束，滚动也不能先结束。
- 位移已经结束，滚动也必须同时结束。
- 不能出现“球体已经停在目标位置，但还在原地继续旋转”的情况。

实现上必须满足：

- 旋转角度与位移距离成正比。
- 位移动画时长与旋转动画时长一致。
- 位移缓动曲线与旋转缓动曲线保持一致。

## 4. 粒子系统规则

### 4.1 粒子的本质

拖尾粒子不是一次性爆发特效，也不是每次都重新随机铺满轨道的全局特效。

它更接近：

- 行星向右移动时，在已经经过的轨道区间内“留下来的痕迹”
- 这些痕迹会持续保留在轨道上
- 行星向左移动时，会像球体从右向左回滚，并逐步把这些痕迹遮掉

### 4.2 向右移动时

当行星从左往右移动时：

- 只有行星刚刚经过的那一段轨道会新增粒子
- 已经出现的粒子不会消失
- 已经出现的粒子会继续保留在原位
- 新增粒子的位置需要有一定随机性，避免机械感
- 但随机性只能发生在“当前新增的那一段区间内”，不能导致全轨道粒子整体乱跳

### 4.3 向左移动时

当行星从右往左移动时：

- 不新增新的拖尾粒子
- 已经存在的粒子会随着行星向左回滚，被逐步遮盖或清除
- 清除顺序必须和行星回退路径一致
- 不能出现左移时仍然在继续往前生成拖尾的情况

### 4.4 粒子保留逻辑

粒子不是“每次播放一遍然后自动消失”。

正确行为：

- 向右移动：新增并保留
- 停止不动：保持当前状态
- 向左移动：从右往左按路径逐步消失

也就是说，粒子状态是“累计式”的，不是“瞬时式”的。

## 5. 颜色与效果变化规则

### 5.1 变化依据

粒子颜色和视觉效果需要随着“程度区间”变化而变化。

例如：

- 稳定附近的粒子偏冷静、克制
- 平衡附近的粒子过渡更柔和
- 发散/创造附近的粒子更活跃、更明亮或更高能

### 5.2 变化范围

这一点是本次实现的关键约束：

- 不是全轨道已有粒子统一变色
- 不是当前程度一改，所有历史粒子一起跟着变
- 只有“当前这次新增出来的粒子”采用它所属区间的颜色和效果

也就是说：

- 粒子一旦在某个区间生成，它就保留该区间对应的视觉风格
- 后续行星去到别的区间，新产生的粒子才使用新的颜色和效果
- 轨道上最终可能同时存在多种不同区间留下来的粒子风格

## 6. 随机性的正确边界

允许的随机性：

- 新粒子在当前新增区间内出现轻微位置偏移
- 粒子大小、亮度、模糊、拖影长度存在小幅波动
- 同一区间重复经过时，新增粒子表现不必完全一致

不允许的随机性：

- 全轨道粒子整体重新洗牌
- 已存在粒子的位置持续抖动或跳变
- 每次更新都重建全部粒子，导致视觉状态不连续

## 7. 建议实现方案

### 7.1 行星动画层

建立一个独立的“物理滚动状态”：

- 当前实际位置
- 目标位置
- 上一帧位置
- 当前旋转角度

动画更新方式：

- 用户点击后，不直接把 CSS 变量瞬间切到目标值
- 使用单一 GSAP tween 驱动“实际位置”持续逼近“目标位置”
- 在 `onUpdate` 中根据位移增量实时累加旋转角度
- 这样可以保证“走多少、转多少”，不会出现位移和滚动脱节

### 7.2 粒子数据层

不要只靠一组静态 DOM 粒子做全局开关显隐。

建议维护一组“轨道采样点”或“粒子槽位”数据，每个槽位记录：

- 是否已被激活
- 激活时属于哪个程度区间
- 该槽位的随机偏移
- 该槽位的大小、亮度、模糊、拖影参数

向右移动时：

- 把“上一次位置”到“当前位置”之间新经过的槽位标记为激活
- 这些槽位一旦激活就保留

向左移动时：

- 把“当前位置右侧、且被行星回退覆盖到”的槽位逐步关闭

### 7.3 粒子视觉层

每个粒子槽位的样式由其“首次激活时的区间主题”决定。

也就是：

- 粒子颜色
- 光晕强度
- 模糊半径
- 尾迹形状

都绑定在粒子自身的数据上，而不是绑定在当前滑块全局状态上。

## 8. 验收标准

完成后需要满足以下结果：

1. 点击任意程度时，行星会像有重量一样滚过去，不是瞬移。
2. 行星位移和滚动严格同步，不再出现“到了还在转”。
3. 向右移动时，轨道后方粒子逐步累积保留。
4. 向左移动时，粒子按回退路径被逐步遮盖消失。
5. 不同区间新增的粒子会保留各自对应的颜色与效果。
6. 已存在粒子不会因为当前程度变化而整体统一重算样式。
7. 随机性只体现在“新生成粒子”的局部表现，不破坏整体稳定性。

## 9. 开发注意事项

- 优先复用现有 `gsap`
- 不盲目引入新库
- 不写测试展示用文案
- 不增加与本需求无关的额外动画
- 保持代码模块化，避免把所有逻辑堆在一个 effect 里
