# VOID 主动监听与唤醒判定策略

> 文档作用：定义 VOID 何时听、何时回应、何时忽略用户环境中的无效语音。  
> 核心原则：用户明确同意后才监听；监听期间也不能乱回应。

## 1. 默认监听策略

VOID 默认不开启主动监听。

规则：
- 软件启动后，麦克风默认关闭。
- 用户开始一次对话并明确授权后，当前对话期间可以保持监听。
- 用户结束对话、关闭会话或重新打开软件后，监听恢复关闭。
- UI 必须有明确但克制的监听状态反馈。

## 2. 两种唤醒方式

VOID 同时支持：

1. 唤醒词唤醒。
2. 判断唤醒。

### 2.1 唤醒词唤醒

默认唤醒词：

- `hello void`
- `hi void`
- `你好 void`
- `你好VOID`
- `VOID`

唤醒词命中后，VOID 进入 listening 状态。

### 2.2 判断唤醒

判断唤醒用于用户没有说唤醒词，但语义明显是在和 VOID 说话的情况。

可判定为唤醒的信号：

- 用户使用第二人称并提出请求：`你帮我想一下`。
- 用户说出明显指令：`帮我记一下`、`提醒我`、`查一下`。
- 用户延续前文话题：`刚才那个问题继续说`。
- 用户看向屏幕或软件处于前台，并出现明确提问。

不应唤醒的信号：

- 用户明显在和旁边的人说话。
- 用户自言自语但没有请求。
- 背景电视、视频、音乐、人声。
- 只有语气词、碎片词、无上下文低音量内容。
- 与最近对话完全无关且不包含请求。

## 3. 无效语音判定

不能只靠音量判断“废话”。音量只能作为参考。

推荐综合判断：

| 信号 | 用途 |
|---|---|
| 音量 | 过滤远处背景声，但不能单独决定 |
| 语义完整度 | 判断是否有明确请求或话题 |
| 上下文相关性 | 判断是否延续当前对话 |
| 唤醒词 | 强信号 |
| 说话方向/设备前台 | 辅助判断 |
| 连续片段 | 避免一句碎片话误触发 |

## 4. 监听状态机

建议状态：

- `mic_off`：麦克风关闭。
- `standby`：用户授权后待机监听。
- `wake_detected`：唤醒词或判断唤醒命中。
- `listening`：正在听用户说话。
- `thinking`：正在转写、理解、生成回复。
- `speaking`：VOID 正在回答。
- `ignored`：识别为无效语音，不回应。

## 5. 回应门槛

VOID 只有满足以下任一条件才回应：

- 明确唤醒词。
- 明确请求。
- 与当前对话强相关的追问。
- 用户明显等待 VOID 回应。

否则只记录临时音频状态，不生成回复，不写入长期记忆。

## 6. 隐私边界

- 未授权时不得监听。
- 无效语音不得写入长期记忆。
- 背景人声不得默认转成用户记忆。
- 长期监听期间应有 UI 状态提示。
- 用户应能一键关闭监听。
