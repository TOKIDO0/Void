# VOID 记忆系统与分区知识库架构

> 文档作用：定义 VOID 如何分块记忆、如何自我学习、如何避免把不同类型信息混在一起。  
> 第一阶段目标：先实现清晰的数据结构和本地存储规则，不追求复杂 AI 自主进化。

## 1. 记忆系统目标

VOID 的记忆不是简单聊天摘要，而是分区知识库。不同信息进入不同分区，需要时按需召回，避免把健康、偏好、待办和情绪混成一团。

## 2. 记忆分区

MVP 阶段建议建立以下分区：

| 分区 | 存储内容 | 示例 |
|---|---|---|
| 用户画像 | 昵称、称呼、语言偏好、重要身份 | 用户喜欢被叫“小陈” |
| 情绪状态 | 最近情绪走势、压力源、低落周期 | 最近三天都提到焦虑 |
| 长期目标 | 用户反复提到的目标和计划 | 想做一个 AI Agent 产品 |
| 健康档案 | 用户本人或亲属健康信息 | 用户本人睡眠差，母亲血压偏高 |
| 人际关系 | 重要人物、关系状态、沟通困扰 | 用户和朋友最近有矛盾 |
| 偏好习惯 | 作息、表达习惯、回复风格偏好 | 不喜欢太长回复 |
| 任务待办 | 明确时间、任务、提醒事项 | 明天要交报告 |
| 专业知识缓存 | 已查过且可复用的专业资料摘要 | 某疾病科普来源于 WHO 或医院官网 |

## 3. 写入规则

默认允许 VOID 自动记录普通记忆，因为数据保存在本地，不上传到 VOID 的服务器。

但以下信息建议提供设置开关：

- 是否允许自动记录健康信息。
- 是否允许自动记录亲属信息。
- 是否允许自动记录情绪趋势。
- 是否允许记录长期目标和待办。
- 是否在写入敏感记忆前弹出确认。

推荐默认值：

- 普通偏好：自动记录。
- 待办事项：自动记录，但可撤销。
- 健康信息：自动记录到本地，但设置页提供“敏感信息写入前确认”开关。
- 身份证、银行卡、密码、密钥：永不记录。

## 4. 召回规则

VOID 不应该每次都把所有记忆塞进 prompt。应根据用户当前问题按需召回：

- 询问健康：召回健康档案 + 用户画像。
- 情绪倾诉：召回情绪状态 + 近期相关上下文。
- 任务整理：召回任务待办 + 长期目标。
- 专业问题：召回专业知识缓存 + 当前模型检索结果。
- 人际关系：召回人际关系 + 情绪状态。

## 5. 自我学习边界

VOID 可以学习用户，但不能假装拥有不可控的“自我意识”。

允许：
- 学习用户说话节奏。
- 学习常聊话题。
- 学习用户喜欢的回复长度。
- 学习用户对耿直和安抚的接受程度。

禁止：
- 自行创造用户没说过的事实。
- 把推测当成记忆。
- 把亲属信息记到用户本人档案。
- 将专业结论长期缓存为绝对真理。

## 6. 数据结构建议

每条记忆至少包含：

- `id`：唯一标识。
- `memoryType`：分区类型。
- `subjectType`：用户本人、亲属、朋友、其他。
- `subjectName`：具体人物名或关系名。
- `content`：记忆内容。
- `confidence`：置信度。
- `source`：来自哪次对话或用户确认。
- `sensitivity`：普通、敏感、高敏感。
- `createdAt`：创建时间。
- `updatedAt`：更新时间。
- `expiresAt`：可选，短期记忆过期时间。

## 7. 模块化实现要求

记忆系统必须独立成模块，不得散落在 UI、prompt 拼接或模型请求代码里。

建议 owner：

- `memoryStore`：本地读写。
- `memoryClassifier`：判断该写入哪个分区。
- `memoryRetriever`：按任务召回。
- `memoryPolicy`：敏感信息和写入策略。
- `memoryProjection`：把记忆转成模型可读上下文。
