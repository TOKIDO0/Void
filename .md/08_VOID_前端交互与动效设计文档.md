# VOID 前端交互与动效设计文档

> 文档作用：定义 VOID Web MVP 的主界面、视觉风格、前端状态机，以及主视觉 Blob 的实现原则。  
> 组件来源限制：Ali Imam Registry，地址 `https://aliimam.in/docs/registry`。不得随意混用多个组件库。

## 1. 总体视觉

主界面必须保持极简，并统一围绕“黑暗中的单体存在感”展开：

- 纯黑背景。
- 页面主体不再是 `0/1` 构成的脸。
- 页面主体改为一个位于画面中心的单色发光有机 Blob。
- 底部保留一个收起状态的极简胶囊输入区。
- 不做满屏装饰背景。
- 不做复杂按钮堆叠。
- 不做霓虹紫、赛博朋克、军绿等过时风格。

当前前端的核心目标不是“展示具体五官”，而是通过一个有生命感、会呼吸、会响应状态的发光存在体，让用户第一眼感知到 VOID 在场。

## 2. 页面结构

建议层级：

1. `VoidStage`：全屏黑色舞台。
2. `BlobScene`：React Three Fiber 的 3D 主视觉场景容器。
3. `VoidBlob`：主视觉 Blob，本体几何、Shader、状态响应都在这里完成。
4. `GroundLight`：极轻微接地感的底部光影。
5. `VoiceCapsule`：底部胶囊。
6. `AudioWaveform`：用户说话或 VOID 说话时的声波。
7. `HiddenSettingsTrigger`：弱化设置入口。

这里的重点是：3D 主体、底部胶囊、状态机，三者必须是独立模块，不要把 Shader、状态切换、胶囊 UI 写成一团。

## 3. 视觉主体定义

### 3.1 主体形态

- 使用 `IcosahedronGeometry`。
- `detail` 固定为 `100`。
- 使用 `ShaderMaterial` 自定义顶点与片元逻辑。
- 外观是“单色发光有机体”，不是金属球，不是果冻，不是彩虹流体。

### 3.2 颜色方向

- 主体基色：深蓝 `#0A0AFF`。
- 边缘 Fresnel 光：亮青蓝 `#00CFFF`。
- 整体必须保持单色系，只允许明暗变化，不做多色混合。
- 不要 Iridescent，不要彩虹反射，不要油膜质感。

### 3.3 背景与环境

- 背景必须是纯黑。
- 环境总体是黑暗、空、静。
- Blob 下方允许有极轻微点光源阴影投射，让主体有一点接地感。
- 除此之外不要增加额外场景元素，不要加网格地面、粒子雨、星空、雾海等会分散注意力的东西。

## 4. 前端状态机

核心状态：

| 状态 | 说明 | Blob | 胶囊 |
|---|---|---|---|
| `idle` | 空闲 | 正常呼吸，深蓝主色，慢速变形 | 收起胶囊，低亮度 |
| `listening` | 用户讲话 | Bloom 更亮，边缘光更强，变形稍加速 | 胶囊展开，显示用户声波 |
| `thinking` | 模型思考 | 整体轻微缩小，颜色变冷偏紫蓝，呼吸更收敛 | 胶囊收缩为球状或高聚焦态 |
| `speaking` | VOID 回复 | Bloom 随 TTS 音量实时变化，边缘光闪烁 | 胶囊展开，显示 VOID 声纹 |

状态机要服务真实产品链路，后续会接 Agent 状态，不要把视觉状态写死在单个组件内部。

## 5. 主视觉技术路线

### 5.1 技术选型

主视觉直接采用：

- `React Three Fiber`
- `GLSL 自定义 Shader`
- 后处理 Bloom

这部分已经不是原来那个 `0/1` Canvas 路线，因此不再保留旧的“字符脸渲染”为主方案。

### 5.2 顶点 Shader 规则

形状变形要求如下：

- 引入 `simplex noise`，使用 `snoise 3D`。
- 使用两层 FBM 叠加：
- 第一层：大尺度慢变形，频率 `0.8`。
- 第二层：小尺度表面细节，频率 `2.5`。
- `uAmplitude = 0.28`。
- `uTime` 驱动整体变形。
- 节奏要明显慢于常见彩虹流体球，强调“呼吸感”，不是躁动感。

### 5.3 片元 Shader 规则

颜色与光感要求如下：

- 主体颜色：深蓝 `#0A0AFF`。
- Fresnel 边缘光颜色：亮青蓝 `#00CFFF`。
- Fresnel power：`2.5`。
- 表面中心略暗，边缘更亮，形成轻微次表面散射感。
- 无 Iridescent。
- 无多色渐变。
- 无高饱和杂色。

## 6. 后处理规范

- 使用 Bloom effect。
- `intensity: 2.5`
- `luminanceThreshold: 0.1`
- 不加 `ChromaticAberration`

后处理目标是让主体更有能量感，而不是做花哨视觉污染。

## 7. 动画规则

### 7.1 呼吸动画

- Blob 整体 `scale` 在 `0.97` 到 `1.03` 之间缓慢循环。
- 周期 `3s`。
- easing 使用 `sine.inOut`。

### 7.2 运动原则

- 动作必须慢、稳、连续。
- 不要突然抽动。
- 不要高频抖动。
- 不要像游戏特效那样夸张形变。
- 呼吸、变形、辉光变化要统一成一个生命体节奏。

### 7.3 胶囊动效

胶囊部分原有原则保留：

- `idle` 保持收起与低亮度。
- `listening` 展开并显示用户输入声波。
- `thinking` 收缩为高聚焦形态，允许做流体感过渡。
- `speaking` 恢复胶囊并显示 VOID 声纹。

胶囊的存在是辅助交互，不得抢主视觉主体的注意力。

## 8. 状态响应映射

### `idle`

- 正常呼吸。
- 主色保持蓝色。
- Bloom 维持基准值 `2.5`。
- 变形速度最慢。

### `listening`

- Bloom intensity 提高到 `3.0`。
- 边缘光更亮。
- 形变速度轻微增加。
- 仍然保持克制，不要做成“激活警报灯”。

### `thinking`

- 整体 scale 轻微缩小到约 `0.92`。
- 颜色向 `#2200FF` 方向偏移，形成更冷的深紫蓝。
- 呼吸感收窄，像在内收聚焦。

### `speaking`

- Bloom intensity 随 TTS 音量实时变化。
- 变化区间 `2.5` 到 `4.0`。
- 边缘光允许随音量做轻微闪烁。
- 说话响应要跟音量绑定，不要伪随机乱跳。

## 9. GSAP 使用规范

必须优先使用 GSAP 完成前端状态驱动和 2D UI 动效。

React 项目要求：

- 使用 `gsap` 和 `@gsap/react`。
- 优先使用 `useGSAP`。
- 所有选择器必须通过 scope 限定。
- 组件卸载时必须清理动画。
- 多段动画使用 `gsap.timeline()`，不要靠一堆 `delay` 硬排。

说明：

- 3D Blob 本体的实时参数变化可以由 R3F render loop 驱动。
- 胶囊、入场、切态、布局层动画继续由 GSAP 驱动。
- 不要让 GSAP 直接逐帧接管整个 Shader 时间主循环。

## 10. 组件库限制

所有通用 UI 组件优先来自 Ali Imam Registry。

规则：

- 不得混用 Shadcn、MUI、Ant Design 等其他组件库，除非用户明确批准。
- 如果 Ali Imam Registry 没有对应组件，可以写本地轻量组件。
- 本地组件必须遵守 VOID 的极简视觉，不得引入不一致审美。
- 设置页、弹窗、输入、开关等优先按 Ali Imam Registry 的组件风格实现。

这部分属于通用约束，继续保留，不受主视觉从“字符脸”切换到“Blob”影响。

## 11. 设置入口与错误反馈

主界面不能显眼堆 UI。

可保留：

- 极弱化设置入口。
- 麦克风授权状态。
- 模型连接错误提示。
- 一键关闭监听。

错误提示应克制，例如胶囊短暂变红，或出现一行短文本，不要弹出大面积打断式 UI。

## 12. 实现边界

当前阶段只定义前端视觉与交互，不直接开始写业务接线。

当前文档明确支持的前端实现边界：

- 先完成黑暗舞台 + Blob 主体 + 底部胶囊。
- 再完成 `idle / listening / thinking / speaking` 四状态的视觉切换。
- 再接 Agent 状态机、音量驱动和真实语音链路。

不在这一阶段解决：

- LLM 接入。
- STT / TTS 真链路。
- 记忆系统。
- 健康档案。
- Tauri 打包。
