# VOID 前端交互与动效设计文档

> 文档作用：定义 VOID Web MVP 的主界面、视觉风格、状态机和 GSAP 动效实现原则。  
> 组件来源限制：Ali Imam Registry，地址 `https://aliimam.in/docs/registry`。不得随意混用多个组件库。

## 1. 总体视觉

主界面必须极简：

- 黑色背景。
- 只有脸部区域由 0 和 1 构成。
- 底部一个收起状态的胶囊输入区。
- 不做满屏 0/1 背景。
- 不做复杂按钮堆叠。
- 不做过时霓虹紫、赛博朋克、军绿色等风格。

你的判断是对的：只让“脸”的部分由 0/1 组成，比满屏 0/1 更高级，也更聚焦 VOID 的存在感。

## 2. 页面结构

建议层级：

1. `VoidStage`：全屏舞台。
2. `BinaryFace`：0/1 脸部主体。
3. `FaceExpressionLayer`：眼睛、嘴部、眨眼、偏视线。
4. `VoiceCapsule`：底部胶囊。
5. `AudioWaveform`：用户说话或 VOID 说话时的声波。
6. `HiddenSettingsTrigger`：极弱化设置入口。

## 3. 状态机

核心状态：

| 状态 | 说明 | 脸部 | 胶囊 |
|---|---|---|---|
| idle | 空闲 | 微弱呼吸光，偶尔眨眼 | 收起胶囊，低亮度 |
| listening | 用户讲话 | 眼神聚焦，嘴闭合 | 胶囊展开，显示用户声波 |
| thinking | 模型思考 | 视线轻微游离 | 胶囊收缩为球状，内部流体动画 |
| speaking | VOID 回复 | 嘴部明暗模拟开合 | 胶囊展开，显示 VOID 声纹 |

## 4. GSAP 使用规范

必须优先使用 GSAP 实现复杂动效。

React 项目要求：

- 使用 `gsap` 和 `@gsap/react`。
- 优先使用 `useGSAP`。
- 所有选择器必须通过 scope 限定。
- 组件卸载时必须清理动画。
- 多段动画使用 `gsap.timeline()`，不要靠一堆 delay 硬排。

性能要求：

- 优先动画 `transform`、`opacity`、`scale`、`x`、`y`。
- 避免频繁动画 `width`、`height`、`top`、`left`。
- 胶囊变球如需视觉变形，优先用 scale、clip-path 或容器投影方式实现；必要时才改实际尺寸。
- 高频音频可视化不要每帧创建新 tween。
- 使用 `gsap.utils.clamp`、`mapRange`、`interpolate` 映射音量到动画幅度。
- 尊重 `prefers-reduced-motion`。

## 5. 0/1 脸部实现路线

MVP 推荐：

- Canvas 或 DOM 网格绘制 0/1 字符。
- 使用亮度、透明度、字符密度塑造脸部轮廓。
- 眼睛、嘴部区域单独分层控制。
- 眨眼通过眼部遮罩或字符亮度变化实现。
- 嘴部通过明暗节奏模拟开合。

不要一开始上复杂 3D 或 shader，除非 MVP 已经稳定。

## 6. 胶囊动效

### idle

- 宽度较小。
- 透明度低。
- 轻微呼吸。

### listening

- 胶囊展开。
- 内部显示用户声音波形。
- 波形颜色偏冷白、青灰。

### thinking

- 胶囊自然收缩成球。
- 动画像 Siri 一样流畅，但不能照搬苹果视觉。
- 内部做柔和流体或脉冲。

### speaking

- 球恢复胶囊。
- 显示 VOID 的声纹波动。
- 可使用蓝、青、少量紫作为点缀，但不能变成紫色霓虹主题。
- 声纹允许 1px 外发光。

## 7. 组件库限制

所有通用 UI 组件优先来自 Ali Imam Registry。

规则：

- 不得混用 Shadcn、MUI、Ant Design 等其他组件库，除非用户明确批准。
- 如果 Ali Imam Registry 没有对应组件，可以写本地轻量组件。
- 本地组件必须遵守 VOID 极简视觉，不得引入不一致审美。
- 设置页、弹窗、输入、开关等优先按 Ali Imam Registry 的组件风格实现。

## 8. 设置入口

主界面不能显眼堆 UI。

可保留：

- 极弱化设置入口。
- 麦克风授权状态。
- 模型连接错误提示。
- 一键关闭监听。

错误提示应克制，例如胶囊短暂变红或显示一行短文本，不要弹出大面积干扰 UI。
