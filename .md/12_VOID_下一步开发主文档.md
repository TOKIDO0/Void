# VOID 下一步开发主文档

> 文档作用：只保留当前真正还没完成、并且接下来必须推进的开发计划。  
> 使用方式：新开窗口继续开发时，先读本文档，再按本文档指向去读执行文档。  
> 文档边界：本文档不再写阶段性大类目标，不记录已完成内容，只写“下一步还剩什么”。

## 1. 当前结论

`Web MVP` 当前已经完成：

- 界面主体和主要动效
- 文本输入到模型回复的主闭环
- 多个基础 Provider 接入
- 真实流式回复渲染
- 当前会话本地持久化
- 正式代理链路前端接入位
- 模型配置面板主流程收尾

这意味着上一轮“文本对话主链路稳定化”已经完成，接下来不再围绕文本回复层继续打磨，而是正式进入 `09` 里下一批真正影响 MVP 体验边界的功能。

## 2. 下一步只做这 4 件事

### 2.1 第一优先级：语音第一闭环

当前状态：

- “思考模式”真实功能已完成
- “上传文件”文本类闭环已完成
- 已有麦克风授权和音量检测预览
- 但 `todo` 里“默认关闭监听”“STT”“TTS”仍未完成
- 当前还没有最终锁定服务端第三方语音厂商与接口契约

下一步目标：

- 先锁定语音供应商方案，再开始正式接入
- 完成默认关闭监听
- 完成语音输入转文本和文本回复转语音的第一闭环
- 让 `speaking` 状态真正与真实 TTS 输出绑定
- 让语音链路与当前文本主链路统一，不做第二套消息系统

### 2.2 第二优先级：人格与安全边界验证

当前状态：

- VOID 人格设计和 system prompt 已接入
- 但情绪稳定性、善意谎言边界和高风险安全边界还没有系统验证

下一步目标：

- 把人格和安全边界从“文档已定义”推进到“可验证、可修正”
- 为后续记忆系统、健康档案和语音能力打基础

## 3. 当前明确不进入下一步主线的内容

下面这些虽然还没做，但不是当前这份“下一步开发主文档”的主线：

- MiniMax provider
- Ollama provider
- 自定义 JSON 请求模板
- 记忆系统
- 健康档案
- 桌面端

这些内容继续留在 `todo` 中管理，但不进入当前下一步计划。

## 4. 完成标准

当下面两件事都完成时，再进入下一轮计划整理：

1. 语音第一闭环完成，包括默认关闭监听、STT、TTS 与 `speaking` 绑定。
2. 人格与安全边界验证完成，并能明确后续修正项。
