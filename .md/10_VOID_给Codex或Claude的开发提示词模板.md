# VOID 给 Codex 或 Claude 的开发提示词模板

> 文档作用：提供后续正式开发时可直接复制给 AI 的提示词。  
> 使用规则：每次只发当前阶段需要的文档，不要一次把所有文档都丢给 AI。

## 1. 静态前端页面提示词

```text
你现在负责开发 VOID 的 Web MVP 静态主界面。

请阅读：
1. 01_VOID_产品定位与边界文档.md
2. 08_VOID_前端交互与动效设计文档.md

任务：
1. 先不要接入 LLM、STT、TTS。
2. 实现全屏黑色背景。
3. 实现中央单色发光 Blob 主体区域。
4. 实现底部收起状态的胶囊输入区。
5. 不要擅自添加多余 UI。
6. 组件库限制为 Ali Imam Registry：https://aliimam.in/docs/registry
7. 代码必须模块化，Blob、胶囊、舞台、动效逻辑拆成独立组件或模块。
8. 不要写测试代码。

完成后告诉我修改了哪些文件，以及如何查看效果。
```

## 2. GSAP 状态机提示词

```text
你现在负责为 VOID 主界面实现 GSAP 动效和状态机。

请阅读：
1. 08_VOID_前端交互与动效设计文档.md

任务：
1. 实现 idle / listening / thinking / speaking 四个状态。
2. 使用 GSAP 和 @gsap/react。
3. React 动画必须使用 useGSAP 或 gsap.context，并正确 cleanup。
4. 多段动画使用 gsap.timeline，不要用大量 delay 硬排。
5. 胶囊需要在 listening 展开，在 thinking 变为球状，在 speaking 恢复胶囊。
6. Blob 需要有呼吸、辉光变化、状态响应，并在 speaking 时跟音量联动。
7. 可先用键盘快捷键模拟状态切换。
8. 不要接入真实语音和模型。
9. 不要写测试代码。
```

## 3. 模型配置和文本对话提示词

```text
你现在负责接入 VOID 的文本对话第一闭环。

请阅读：
1. 03_VOID_System_Prompt正式版.md
2. 07_VOID_技术架构与模型接入文档.md

任务：
1. 实现模型配置模块。
2. 第一版至少支持 OpenAI-compatible API。
3. 用户可以配置 API Key、Base URL、Model Name。
4. 对话请求必须注入 VOID system prompt。
5. Provider 必须模块化，UI 不得直接依赖某个厂商 SDK。
6. 回复过程中切换前端 thinking / speaking 状态。
7. 不要写测试代码。
```

## 4. 分区记忆提示词

```text
你现在负责实现 VOID 的本地分区记忆 MVP。

请阅读：
1. 04_VOID_记忆系统与分区知识库架构.md
2. 05_VOID_健康档案与敏感信息治理文档.md

任务：
1. 实现用户画像、情绪状态、偏好习惯、任务待办四个基础分区。
2. 预留健康档案分区，但不要做诊断功能。
3. 每条记忆必须有类型、主体、内容、置信度、敏感等级、来源、时间。
4. 记忆可以查看和删除。
5. 不要把记忆逻辑写在 UI 组件里。
6. 不要写测试代码。
```

## 5. 主动监听提示词

```text
你现在负责设计并实现 VOID 的主动监听和唤醒策略。

请阅读：
1. 06_VOID_主动监听与唤醒判定策略.md
2. 08_VOID_前端交互与动效设计文档.md

任务：
1. 默认关闭麦克风监听。
2. 用户授权并开始当前对话后，可以在本轮对话期间常开。
3. 支持 hello void、hi void、你好 void、VOID 等唤醒词。
4. 支持判断唤醒，但必须有明确回应门槛。
5. 无效语音不得写入长期记忆。
6. UI 需要显示克制的监听状态。
7. 不要写测试代码。
```
