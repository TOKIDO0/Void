# VOID MVP 阶段任务拆分

> 文档作用：把 VOID 第一阶段拆成可交给 Codex / Claude 分步完成的任务。  
> 核心原则：不要一次让 AI 从零完成整个项目。

## 阶段 1：静态 Web 主界面

目标：
- 搭建黑底全屏页面。
- 实现 0/1 脸部主体。
- 实现底部胶囊输入区。

不做：
- LLM。
- STT。
- TTS。
- 真实设置页。

验收：
- 页面视觉符合 VOID。
- 没有多余 UI。
- 移动端和桌面端不重叠。

## 阶段 2：前端状态机和 GSAP 动效

目标：
- 实现 idle / listening / thinking / speaking。
- 用键盘或临时内部控件模拟状态切换。
- 实现胶囊展开、变球、恢复胶囊。
- 实现脸部眨眼、嘴部开合、呼吸光。

要求：
- 使用 GSAP timeline。
- React 使用 `@gsap/react`。
- 动画有 cleanup。
- 不写测试代码。

## 阶段 3：模型配置和文本对话

目标：
- 实现模型配置页。
- 支持 OpenAI-compatible API。
- 接入 VOID system prompt。
- 完成文本输入到模型回复的第一闭环。

要求：
- Provider 模块化。
- UI 不直接调用厂商 SDK。
- 错误提示克制。

## 阶段 4：多 Provider 适配

目标：
- 增加 Anthropic、DeepSeek、MiniMax、智谱、Ollama 等适配。
- 支持用户自定义 Base URL 和 JSON 请求模板。

要求：
- 所有 provider 走统一 contract。
- 不写大量散落 if 兼容。

## 阶段 5：记忆系统 MVP

目标：
- 实现本地分区记忆。
- 支持用户画像、情绪状态、偏好习惯、任务待办。
- 记忆可查看、删除。

暂不做：
- 复杂向量数据库。
- 自动长期知识图谱。

## 阶段 6：健康档案

目标：
- 用户本人和亲属健康档案分开。
- 只在用户提及时动态建档。
- 健康信息不混淆人物。

要求：
- 不诊断。
- 不给用药建议。
- 高风险场景提醒就医。

## 阶段 7：语音和主动监听

目标：
- 麦克风授权。
- STT。
- TTS。
- 唤醒词和判断唤醒。
- 无效语音过滤。

要求：
- 默认关闭监听。
- 当前对话期间用户授权后可常开。
- 结束对话或重启软件后恢复关闭。

## 阶段 8：Tauri 桌面端

目标：
- 将 Web MVP 打包为桌面 App。
- 本地 SQLite 存储。
- 权限适配。

前置条件：
- Web 视觉和对话体验已经稳定。
